# Kotoba Lock (Electron)

A 1:1 Electron port of the Python **Word Lock** app, retargeted to a
**Japanese → Vietnamese** dictionary. The gate shows a Japanese word, its kana
reading and a romaji hint; the user unlocks it by typing the romaji.

The Electron app intentionally uses a different identity from the Python build
so both can be installed and used side by side:

| | Python app | Electron app |
|---|---|---|
| Window title | Word Lock | **Kotoba Lock** |
| Executable | `WordLock.exe` | `KotobaLock.exe` |
| Tray / Run key | `WordLock` | `KotobaLock` |
| Data folder | `%USERPROFILE%\wordlock` | `%USERPROFILE%\kotobalock` |

## Run

```bat
npm install
npm start
```

Build a Windows installer / executable:

```bat
build.bat
```

or directly:

```bat
npm run dist
```

`npm start` and `npm run dist` rebuild the Tailwind stylesheet automatically
(`prestart` / `predist`). To rebuild it on its own:

```bat
npm run tailwind
```

## Styling and scripts

- **Tailwind only.** The three hand-written CSS files were removed. The single
  stylesheet is `src/tailwind.css`, generated by `scripts/build-tailwind.js`
  from `@tailwind` directives plus `@apply` component utilities. No custom
  stylesheet is maintained by hand.
- **jQuery.** `jquery.min.js` is loaded locally by every window and used for
  DOM building, events and state updates in `src/renderer.js`,
  `src/settings.js` and `src/overlay.js`.
- **Themes.** The ten UI themes are still CSS variables produced by
  `lib/ui-styles.js` and applied by `src/theme.js`; the Tailwind components read
  those variables, so switching a theme remains a single variable update.

## Behaviour ported from the Python app

- Auto-show gate after `AUTO_SHOW_DELAY_MS` (default 60 seconds).
- Bottom-right always-on-top countdown card with `5s`, `04:59`, `1:04:59`
  formatting and a 250 ms refresh.
- Type-the-word gate with a 500 ms auto-accept after a match, incorrect-answer
  feedback, and repeated focus attempts while the window is maximised.
- Least-practiced word selection using `progress.json`, with random tie-breaks.
- Ignore-word button (quiz screen exits; info card reports success).
- Pronunciation playback with a `Listen` button, a `Speaking...` dot animation,
  350 ms debounce, click-to-stop, and automatic playback when the card opens.
- Dictionary card with definitions, examples (with per-example Speak buttons),
  synonyms / antonyms / tags chips, and `Enter to exit`.
- Ten rotating UI styles (`midnight`, `paper`, `terminal`, `sage`, `sunset`,
  `ocean`, `mono`, `royal`, `candy`, `steel`); a random *different* style is
  picked after each completed word. Tray has **Next UI style**.
- Tray menu: Open app, Next UI style, Settings, Start/Stop app, Show countdown,
  Exit.
- Settings modal with delay, volume (0–4×), start-with-Windows and ignore-word
  list; saves `config.json` atomically and validates before writing.
- Per-user `HKCU\...\Run` startup entry (no admin rights) with path repair on
  launch.
- Google Chrome / Chromium is suspended while the gate is visible and resumed
  when it closes (PowerShell + `NtSuspendProcess`, no native addon needed).
- The gate takes the Windows *keyboard* foreground, not just always-on-top
  visibility: `lib/foreground.js` attaches to the foreground thread's input
  queue and calls `SetForegroundWindow` (with `SwitchToThisWindow` as a last
  resort), then `webContents.focus()` plus the answer-input focus run, so typing
  works immediately without clicking the field.
- Closing the window hides it to the tray; `Exit` in the tray quits.
- Single-instance behaviour: launching again focuses the existing gate.

## Data folder

Created on first run:

```
%USERPROFILE%\kotobalock\
├── config.json
└── progress.json

{
  "AUTO_SHOW_DELAY_MS": 60000,
  "IGNORE_WORDS": [],
  "SOUND_VOLUME": 2.0,
  "START_WITH_WINDOWS": false
}
```

`progress.json` stores `{ "version": 1, "attempts": { "りんご": 3 } }`.

## Romaji is computed, never stored

There is no romaji in the dictionary and no per-word romaji table in the code.
Every romaji string in the UI — the gate hint, the accepted answer, the
definition/example lines, synonyms and antonyms — is produced at runtime by
[Kuroshiro](https://github.com/hexenq/kuroshiro) with the Kuromoji analyzer:

```js
const kuroshiro = new Kuroshiro();
await kuroshiro.init(new KuromojiAnalyzer());
await kuroshiro.convert("がっこう", { to: "romaji", mode: "normal" });
// -> "gakkō"
```

The app displays `gakko` (macrons flattened) and accepts the wapuro long-vowel
spellings as well, so `gakko`, `gakkou` and `gakkoo` all unlock the gate. Those
variants are generated algorithmically from the Kuroshiro output.

Because the analyzer needs the Kuromoji dictionary, `kuroshiro`,
`kuroshiro-analyzer-kuromoji` and `kuromoji` must be **production dependencies**
(the package.json already lists them) and must not be bundled into an asar
archive — the project uses `"asar": false`.

## Dictionary schema

Entries live in `database/words/<word>/<word>.json`:

```json
{
  "word": "学校",
  "language": { "source": "ja", "target": "vi" },
  "pronunciation": {
    "kana": "がっこう",
    "audio": ""
  },
  "part_of_speech": "noun",
  "definitions": [
    {
      "japanese": "勉強するための教育機関。",
      "vietnamese": "Trường học."
    }
  ],
  "examples": [
    {
      "japanese": "毎日学校へ行きます。",
      "vietnamese": "Ngày nào tôi cũng đến trường.",
      "audio": ""
    }
  ],
  "synonyms": ["学び舎"],
  "antonyms": [],
  "tags": ["education", "place", "common"]
}
```

`word` is what the gate displays (kanji or kana) and `pronunciation.kana` is
the reading Kuroshiro romanises. Any romaji fields left in older entries are
ignored and stripped before the entry reaches the renderer. Answers are
compared case-insensitively after removing macrons and every non-alphanumeric
character, so `gakko`, `gakkou`, `gakkoo`, `GAKKOU` and `gakkō` are equivalent.

## Adding audio

Audio can be wired in two ways.

**1. Auto-discovery (recommended)** — drop files next to the entry's JSON using
these names; no JSON edits needed:

```
database/words/学校/audios/gakkou.ogg          ← named after any accepted romaji
database/words/学校/audios/学校.ogg             ← or after the word itself
database/words/学校/audios_example/example_1.ogg  ← first example sentence
database/words/学校/audios_example/example_2.ogg  ← second example sentence
database/words/学校/audios_example/gakkou_1.ogg   ← per-word naming also works
```

Files are matched by each Kuroshiro-generated romaji spelling, the JSON filename
or the word itself, in that order. Any supported extension works.

**2. Explicit path** — set `audio` to a path relative to `database/`:

```json
"pronunciation": { "audio": "words/学校/audios/gakkou.ogg" }
```

Supported formats: `.ogg .oga .opus .mp3 .wav .m4a .aac .flac .webm`.
Playback is decoded with the Web Audio API so the `SOUND_VOLUME` gain can go
above 1.0 (up to 4×), matching the Python ffplay volume filter.

## Regenerating the starter dictionary

The starter set (83 entries) is produced from one data file:

```bat
node database\generate_starter.js
```

Edit the `ENTRIES` array in that script to add more words (only `word`, `kana`
and the Vietnamese/example fields — never romaji), then rerun it. The script
also removes the old `database/<letter>/` folders from previous builds. Words
are selected least-practised first, so new entries join the rotation
automatically.
